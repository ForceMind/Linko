# RW04 WebRTC 源码探针

Actions 从固定的 WebRTC 和 depot_tools 提交同步源码及 DEPS，构建一个最小的 VideoFrame 探针。程序生成 I420 测试帧，从 WebRTC API 读回尺寸、采样时间和回绕前后的 RTP 时间戳。两个平台分别上传源码、DEPS 和许可证文件的 Git 标识，以及构建参数和探针结果。仓库只保存探针和配置。

macOS 再从独立 C 文件跨过固定布局的 ABI，使用 WebRTC 的 VideoToolbox H.264 工厂对合成关键帧做本机编解码。保留单帧回归，并在同一组编解码器中验证 18 帧连续流。检查原始尺寸、亮度、关键帧与后续帧、同一会话内 RTP 回绕，以及重复时间戳、倒退时间戳和关闭后的拒绝。无效版本、空指针和超限尺寸返明确错误。

macOS 的窗口探针沿用 RW03 的 ScreenCaptureKit 和 AppKit。专用构建把单窗口像素送入 WebRTC H.264，再由预览控件绘制解码输出。托管机验证红色到绿色、窗口缩放和关闭时清屏。该探针使用系统现有录屏许可，不会请求新许可。

单机传输实验建立两个 WebRTC 端点，在 `127.0.0.1` 上以 UDP 和 DTLS 传送合成 H.264 视频。检查接收帧的尺寸与亮度，关闭端点后重新协商有新 ICE 凭据的连接。端点使用虚拟音频设备和本机生成的视频，测试不连接 STUN/TURN，也不接入用户设备配对。

整链路探针把 ScreenCaptureKit 采集的测试窗口接到同一对回环端点。发送端只发视频，接收端只接视频。AppKit 从最新的解码帧绘制，测试核对绘制像素由红转绿、窗口尺寸变化和来源关闭后清屏。画面留在托管机内存，探针不打包成应用。

撤权回归在来源窗口仍打开时点「停止」，确认清屏、端点关闭和旧采集释放。探针保留旧画面及旧端点再打开同一窗口，将旧帧分别提交到已关闭的媒体端点和旧显示输出，检查拒绝后才确认新画面的像素。

回环解码和 AppKit 层共用单调时钟。一帧从接收端解码回调起保留两秒。等待取帧、像素转换和重复绘制均计入期限。测试分别检查取出帧时保留原始时间，以及 AppKit 的过期清理。

启停回归在同一托管 macOS 窗口上重复 100 次真实采集、传输及呈现。每次停止均检查 ScreenCaptureKit 回执、旧输出销毁、WebRTC 端点关闭、清屏和停止轮询。报告记录停止后的 RSS、线程和描述符数，检查预热后的描述符增长。

预览复用一个 Core Image 渲染上下文。[上下文对照](https://github.com/ForceMind/Linko/actions/runs/45065522785/artifacts/14771209787)记录了两种模式的差异。当前 Actions 在同一 runner 的独立进程分三组各运行 100 次，覆盖整链路、真实单窗口采集加本机绘制、固定合成帧经 H.264 加密回环。报告记录 RSS、物理内存占用、在用堆、分配区容量、线程及描述符。后两组只用于诊断资源变化。

完整回环的采集端用 Core Video 池复用送编 BGRA 缓冲。当前尺寸的池最多分配六个缓冲，全部占用时跳过本帧。尺寸变化时替换池，仍被编解码器持有的旧帧按系统引用生命周期释放。停止时旧采集对象释放池并拒绝继续分配。

只收帧的对照进程沿用完整回环的真实窗口、采集尺寸、像素池、加密端点和停止回执。它在同一显示轮询入口取得解码像素并立即释放，用于区分生成和展示解码图像的开销。

该实验调用系统 H.264。WebRTC 内建 H.264 和专有软件 codec 仍关闭。Windows codec factory、局域网设备信令、远端窗口呈现与分发许可继续按 RW04 方案推进。产物仅包含验证报告。
