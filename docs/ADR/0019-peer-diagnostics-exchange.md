# ADR-0019 两端诊断摘要的可选交换

日期：2026-11-18。状态：草稿实现。验证结果见 PR #312，两台实机未验证。

## 背景

排查单向越边时，用户要在两台电脑之间手工复制 `KVM-DIAG/5` 摘要。需求是在一台
电脑的“高级诊断”里直接看到另一台的摘要和按住状态行。

## 调查结论

- v5 线格式：`Message` 是 serde 外部标签枚举，`decode` 遇到未知变体返回
  “invalid frame”，会话把它当作 `InvalidMessageFrame` 结束连接。直接给旧对端发
  新变体会断开旧对端，不可行。
- 输入连接的 QUIC 初始上限为一条双向流、零条单向流。QUIC 允许双方协商后调整单向流额度。
- `Hello` 是结构体变体，没有 `deny_unknown_fields`。旧解码器会忽略多出的字段。
  `InputCapabilities` 的位图不能借用，它描述注入能力，校验严格。
- 数据连接（ADR-0013）需要数据授权；诊断摘要不是用户数据，也不应依赖数据授权。
- worker 与 GUI 之间已有 stderr 诊断通道，GUI 已从中挑出合法摘要。

## 决定

1. 本机开启“开启并诊断”时，worker 发出的 `Hello` 多带一个字段
   `"peer_diagnostics":2`。其余字段沿用 v5 Hello。未开启诊断时发送的字节
   完全不变。`VERSION`、`ALPN`、`Message` 枚举都不改。
2. 只有双方 Hello 都声明值 2 时，两端才各开放并接收一条单向诊断流。诊断流承载
   `{"PeerDiagnostics":{"summary":…,"held":…,"event":…}}` 帧，优先级低于 v5 输入流。
   缺少字段或带首轮草稿值 1 时，继续原 v5 会话，GUI 显示“另一台未提供诊断”。
3. 发送：会话在 200 ms 定时器里每秒至多一帧，只在诊断窗口有效期内（120 秒），
   每个会话至多 150 帧。载荷只有已通过 `is_summary` 的摘要行、按住状态采样行和
   至多一条拦截事件行，没有输入内容、键码、剪贴板或文件。
4. 接收：诊断流按独立帧格式解码（拒绝未知字段、超长行、非可打印 ASCII），各行再用
   `is_summary` 与 `is_held_line` 校验，任一行不合格则整帧丢弃。两次显示间隔至少
   250 ms。每端最多检查 300 帧，含被丢弃的帧。诊断帧解码或读取失败时停止接收诊断。
   v5 输入流继续按原来的 `InvalidMessageFrame` 规则处理非法帧。
5. 显示：合法行以 `KVM-PEER ` 前缀写入本机 stderr 诊断通道，GUI 再次校验后只按纯
   文本显示，不写盘、不上传、不自动发布。复制由用户点击按钮完成。
6. 诊断交换不读取、不依赖接收控制或输入授权；它只由两端各自的诊断开关决定。没有
   新增远程动作、脚本 RPC、全局钩子或回调内工作。

## 代价与限制

- 诊断流和输入流共享连接带宽。诊断每秒约 2 KB，最多排队一帧。诊断流开启或写入失败时
  只停止该方向的诊断传输。写入超时重置该流，清理可能残留的半帧。
- 交换只覆盖主会话路径（`connect`/`listen`）。分段路由、多对端和 Linux 会话仍使用
  不带此字段的 Hello。
- 任一端为旧版本时只能各自复制摘要。

## 验证

单元测试覆盖：旧解码器读取带字段的 Hello、两端提出组合（真实 QUIC 回环）、诊断帧
严格解码与边界、诊断流损坏与写入超时、原 v5 消息错误分类、发送频率与总量、GUI 存储与复制。
两台实机的 Windows／macOS 互看尚未验证，属于 #3/C06。
