# ADR-0012 macOS 发送侧光标隐藏和恢复

日期 2026-11-12。状态为提案，等待决定。

## 当前行为与参考

Linko 的发送侧现已在远端捕获代次有效时请求解耦鼠标与光标。只有系统
确认成功才登记恢复义务。现有实现不隐藏光标、不创建窗口，也未完成
该候选的双机验收。用户观察到的本机光标和滚轮行为仍需新候选的计数与
实际动作对照。

Oink 固定提交使用公开的光标隐藏与解耦调用，并用非激活 AppKit 面板
协助维持光标属主。在相应路径还按运行时条件解析私有 WindowServer
符号。其 worker 有独立的主线程 AppKit 循环。这里只比较机制，Linko
自行实现所需代码。

- [Oink 的隐藏和解耦](https://github.com/oinkvm/oink/blob/3ca82127e61f9d7106a70574a82cc63566d7a572/crates/oink-input/src/macos/cursor.rs)
- [Oink 的光标属主面板](https://github.com/oinkvm/oink/blob/3ca82127e61f9d7106a70574a82cc63566d7a572/crates/oink-input/src/macos/cursor_owner.rs)
- [Oink 的 worker 主线程](https://github.com/oinkvm/oink/blob/3ca82127e61f9d7106a70574a82cc63566d7a572/crates/oink-agent/src/backend/macos.rs)

## 拟议决策

1. 公开 API 路径先独立验证。原生循环只在当前远端代次、权限和来源
   均有效时请求隐藏。每次成功隐藏登记相同显示器上的一次显示义务，
   与解耦义务分开。任何部分失败均通过本进程拥有的义务逐项撤回。
   显示器变化时先恢复旧显示器的账本，不将义务转给另一显示器。
2. 普通回程、紧急恢复、断连、停止、权限变化、来源丢失和正常退出
   均进入同一恢复路径。过期代次无法再隐藏光标。恢复失败保持待处理
   并拒绝新准入，通过现有本机恢复提示呈现。强制进程结束后的系统
   行为需要真机验证。
3. 如果公开 API 在最终实测中仍会露出光标，可评估独立的非激活、
   不接收点击与焦点的面板。面板的生命周期由 macOS worker 主线程
   管理，现有输入 tap 和授权入口仍只有一个。面板不能在回调中创建、
   操作、等待或执行任何输入。GUI 与 worker 的停止、EOF 和恢复
   回执继续走现有私有通道。
4. 私有 CGS 只作为单独授权的实验候选。只操作本进程创建的窗口，
   动态符号、架构、ABI、属主或退出清理条件不符即保持公开 API 路径。
   默认关闭实验能力。任何正式发布、签名和公证仍需按已有范围批准。
   不更改系统安全设置，不以透明窗口取得新的权限或绕开 Secure Input。

## 验证门槛

Actions 用替身覆盖过时代次、重复隐藏、两项调用部分失败、显示器变化、
停止与恢复重入、超时、关闭回执以及非 macOS 路径。完成版的 C06 检查
包括光标在不同应用和显示器上是否隐藏、返回后的恢复、边缘连续位移、
锁屏／解锁、休眠、撤权、断开与强制退出。使用两端 KVM-DIAG/5 与实际
光标结果对照，区分可见性、解耦、转发与接收注入。
