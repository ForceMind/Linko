# ADR-0014 多设备与副屏路由

日期 2026-11-12。状态为设计草稿。实现需分批验证，副屏间切换尚不可用。

## 本机屏幕与配置

屏幕快照来自本机公开系统 API。Windows 用物理桌面像素，macOS 用
CoreGraphics 桌面点。系统提供的矩形已经按实际方向排列，背板比例
只用于显示和变化检测。负坐标、非对齐的屏幕和重叠区域保留在模型中。
本机屏幕相接的边沿段留给本机光标；可用于跨机的外沿段单独选择。

快照中的屏幕标识由当前查询进程持有。保存跨重启的布局前，平台适配
需要用公开 API 取得可重新解析的本机屏幕标识。无法匹配时提示用户
重新选择，不按序号推断。现有单设备设置只迁移已登记的证书和原方向，
保存失败保留原文件。每台新增设备独立配对，旧许可不复制给新增设备。

## 唯一输入所有者

本机保持唯一的捕获生命周期、接收注入所有者和恢复路径。允许同时
连接多台可信设备，控制所有权仍只有一份。连接由明确登记的精确证书
识别。发现结果、屏幕标识和任何路由标记都不能授予键鼠或内容许可。

路由先匹配本机当前快照的外沿段，再使用用户保存的目标设备和屏幕。
重叠配置拒绝启用并说明冲突位置。同一条入边的一次激活只发起一个
Acquire。切换目标前撤销旧提交并等现有释放回执；回收不确定时保持
本机恢复状态。离线或冲突时光标和按键留在本机，不沿同一边重试其他
目标。回到安全区域后再重新武装。

监听端并发连接的接收请求由同一个本机仲裁器检查。仅在当前会话的
本机接收许可有效、输入所有者空闲且恢复已确认时接受。过期回执、
重复提交及其他会话的序号不能接管已有租约。停止、撤销、权限变化、
屏幕集合变化及断网走原有释放和注入清理。回调只读取预先准备的有限
路由快照，记录事件到现有队列；系统枚举、配置读写和网络协商在回调外。

## v5 兼容与副屏预留

保留 v5 Hello、Acquire、Granted、Input、Release、Ping、Pong、运动
数据报及 peerglide/5 ALPN。旧端继续支持已登记的主屏路由。用户
明确选中副屏时，两端都要支持并确认副屏路由；协商不可用时提示该
路线不可用，保持本机控制。

考虑在现有隔离数据连接上协商一个独立的布局能力。每次副屏预留只
用于一个当前 v5 连接及一个待提交租约，由精确配对证书、域隔离的
QUIC TLS exporter 派生值、预期屏幕和当前两端布局代次绑定。相同
配对下的另一连接不能替换此预留。预留只描述坐标映射，实际接收
还要走 v5 Acquire 与本机键鼠授权。标记仅在认证完成后的连接内
传送，禁止持久化和记录。

预留在等待期限、连接结束、授权变更或布局变化时作废。确认后，
v5 的归一化坐标解释为选定目标屏幕的坐标。主屏模式保留原解释；
副屏模式只在接受并冻结该目标的会话范围内启用。退出副屏路由时先
释放已有注入和捕获归属。

## 验证顺序

1. 纯模型测试覆盖负坐标、贴边、镜像、旋转、DPI 和热插拔代次。
2. GitHub Actions 用三个回环身份测试固定证书、旧 v5、错误连接
   绑定、同边竞争、失联、回收及副屏协商拒绝。验证期不捕获或注入
   原生键鼠。
3. 同一候选包的 #3/C06 物理验收记录多显示器、混合 DPI、热插拔、
   三台设备竞争、蓝牙／USB 及重连恢复。
