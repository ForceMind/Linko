# ADR-0015 跨机拖放的复制投递

日期 2026-11-12。状态为设计草稿。桌面文件页拖入本机文件后可明确发送。
Windows 和 macOS 源应用可通过一次性边沿接收条发起文件投递。拖动会话在目标应用中的
连续接棒仍待实现和验收。

## 本机意图和会话

源端由用户发起实际拖动，已认证的目标电脑需要独立同意此次拖放。
文本、图片和文件沿用对应内容类型的方向许可，另需本机确认投递。
连接或键鼠控制成功不能授予这项许可。既有 v5 报文及 ALPN 保留，
文件和图片使用独立数据连接，接收方只采用已通过边界与内容校验的数据。

边沿接收条是文件页明确开启的一次性原生窗口，只在主屏的可用发送边沿显示。
实际放下单个本机文件后重新核对配对、接收地址、边沿及显示器快照，再交给现有文件
投递。接收端逐次同意。切出文件页、最小化、配对变化、超时或停止会撤回窗口。

每次投递绑定精确证书、当次连接、传输编号、活动的本机拖放代次和
受控的输入归属。失焦、按钮状态失配、取消、连接结束、布局变化或
撤销均关闭旧票据。只接受同一票据的完成回执，异常或结果未知时
提示检查目标应用，禁止自动再投。原生输入只使用现有捕获生命周期。
拖动期间的非复制行为、失效票据或未完成验证不向目标应用提供数据。

已接收文件保留经文件连接认证的证书摘要、传输编号和本机连接随机值。接收页的
复制票据还绑定准备时的本机布局和操作代次。离开接收页或准备期间失焦会撤回准备。
提交和接收结果时复查身份与布局。macOS 在拖动期间检查布局，Windows 同步 OLE
会话返回后核对布局与回执。结果不明时，用户须核对目标应用再重新准备。此路径
当前用于接收端本机拖出，连续跨机接棒仍需和实际输入租约关联。

## 文件暂存与原生交付

文件先进入用户明确选择的接收范围，沿用有界清单、已验证分块、
持久配额和不覆盖发布。原生交付从已验证的本机副本产生，目标位置由
接收端系统和用户的放置动作决定。远端没有指定目标路径、打开文件、
移动或删除源文件的权限。目标拒绝时保留已暂存内容和已知状态。

Windows 的第一条候选路径采用现有 GUI 线程的 OLE 拖动会话，只允许
复制效果。目标能处理本地文件时提供已准备的本机文件数据，虚拟文件
需要同时支持文件描述和内容流。跨进程数据对象的读取放在受控工作器，
主输入回调只做有界状态记录。系统拒绝、焦点变化或用户放开按钮时
终止旧会话并走已有释放路径。

Windows 文件副本入口公开一个 `FileGroupDescriptorW` 和一个只读 `FileContents` 流，
按住时只提供元数据。OLE 确认放置后由工作器从保留的接收文件句柄逐块校验，按需提供
有界片段。同步拖放返回、取消、超时或读取失败后，保留的流失去读取权限。复制状态
要求 OLE 报告复制且内容流完成读取。仅接受路径的目标可用文件引用入口，异步 Shell
目标和实际 Explorer 兼容性留到验收。

macOS 的第一条候选路径使用 AppKit 拖动会话和 NSFilePromiseProvider。
提供者只登记已准备的内容和名称，写入由其操作队列交给本机存储工作器，
收到目标提供的 URL 后再验证本机票据和当前目标。普通文件 URL 和文件承诺
各有目标应用兼容性。与共享容器、File Provider 扩展或签名有关的附加
方案需要独立记录并获授权后才能启用。

macOS 接收文件页候选提供本机文件副本与文件引用两种拖出方式。文件副本从保留的
本机句柄逐块校验，在 AppKit 操作队列和文件协调器给出的目标目录准备后原子发布。
同名目标、取消、超时、内容变化和目标文件系统无法创建硬链接时结束复制。
复制完成回执要求 AppKit 放置结果及文件写入结果都成功。Finder 和其他目标应用
的文件承诺处理留到真实设备验收。

## 连续跨机拖放的验证前提

AppKit 的目标窗口在拖入时可以判断格式和允许的操作，释放鼠标后才进入
`performDragOperation` 交付。文件承诺的写入也在拖动结束后启动。Windows OLE
的 `DragEnter` 可检查格式，Microsoft 建议在实际放置前避免用 `GetData` 渲染内容。
因此边沿接收条以放下文件作为发送意图，连续交接先从 Linko 自有且已授权的源内容
验证。任意源应用的连续交接还需要一条保留复制语义、在松开前交换最少元数据的机制。
慢传输、放手或取消应结束该次接棒并清理归属，目标应用的内容只能在完整校验后交付。

首条连续接棒按以下顺序验证，源端限 Linko 自有拖动区域：

1. 两端先各自确认本次复制，接收端完成文件校验并准备目标窗口。通过独立认证的数据
   协商把已准备的传输与本次 v5 输入连接关联，复用连接导出证明的做法。本机票据随机值
   不出进程，传输编号和已配对证书用于核对，输入许可仍由现有租约单独授予。
2. 源端由现有捕获所有者记录获准区域内的原始左键按下。只有这一个仍持有的按键对可随
   本次拖动跨越边沿。普通按键对继续遵守原有归属。已松开、第二个键按下、旧代次回执、
   失败或超时立即撤销这次接棒。
3. 接收端已同意的窗口收到对应租约的首个左键按下后，才发起本机复制拖放。交付结果和
   按键释放分别核对。断开、撤权或停止先撤销票据并清理已有按键对。

## 验证

GitHub Actions 先覆盖本地拖动票据、拒绝、断线、代次变化、复制效果、
完整性和权限无效化。Windows 和 macOS 分别编译和测试各自适配器。
最终同源候选由用户在 Finder、Explorer 及实际目标应用中验收跨屏
文字、PNG、文件、取消、慢传输、失焦、源文件变化和本机输入恢复。
