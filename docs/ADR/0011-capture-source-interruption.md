# ADR-0011 捕获源暂时中断与本机恢复

日期 2026-11-12。状态为提案，等待决定。对应输入审计 F04。

## 当前行为与证据

Windows 用只读查询确认当前线程与输入桌面相同。查询失败和桌面变化
都变成同一个布尔值。macOS 将辅助功能、输入监控和安全输入合并为
可用性判断。原生循环在检查失败时调用 `CaptureGate::source_lost`，
停止当前捕获。已有证据来自代码。锁屏、睡眠或 Secure Input 是否造成
用户观察到的单向故障仍待双机诊断。

`SourceObservation` 的单调时钟和墙钟共同保护原生效果。持有注入或配对
债务时，过旧观测会使恢复失去可靠性。ADR-0005 只允许已识别的网络故障
自动重试，原生失败和未知恢复结果要求停止。

## 拟议决策

1. 在现有原生循环、回调之外生成有界原因枚举。区分已观察到的短暂输入
   环境中断、明确撤权、线程或 tap 已终止、查询未知。Windows 仅在已
   确认两个桌面不同时报告桌面切换。macOS 仅在权限仍就绪且查询已确认
   安全输入时报告该原因。其余观测保持原有失效处理。
2. 暂时中断也立刻撤回新准入，退休已激活租约和待确认申请，按既有路径
   发释放通知。已拥有的按下与抬起继续由原所有者处理，光标关联恢复
   沿用原有账本。环境不可证明安全时，保留本机恢复未确认及原停机保护。
   不在不明桌面补注入，也不放宽双时钟和所有权检查。
3. 只有旧所有者明确清理并完成退出后，GUI 才能将该中断显示为可重新
   启动。用户重新打开键鼠时重新检查本机权限和已登记身份，启动一个
   新会话与新捕获代次。前一会话的租约、按键、命令和位置不继承。
   自动重连继续按 ADR-0005 的网络故障分类执行。
4. 只在本机工作进程状态中记录原因枚举。GUI 以明确的动作和恢复状态
   反馈，禁止记录桌面名称、按键或位置。输入 v5、ALPN 和设备权限
   使用现有契约。

先实施原因分类与状态回归，再处理 Windows／macOS 各自的观测映射。
同一捕获生命周期拥有安装、撤回与清理。退出未确认时保持当前错误路径。

## 验证门槛

Actions 用替身覆盖每种原因、同一中断重复出现、恢复和停止竞争、权限
撤销、旧代次回执、成对释放失败及清理不明确。严格检查新准入被撤回、
旧状态不复用、未知状态仍失效。最终 C06 由用户验证锁屏／解锁、睡眠／
唤醒、Secure Input、辅助功能和输入监控变化及 Windows 桌面切换。
