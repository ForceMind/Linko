## 4. 自动化验收矩阵

| 编号 | 故障/输入 | 必须结果 |
| --- | --- | --- |
| A01 | 未登记设备、证书变化、伪造发现记录 | 不协商媒体、不授予观看/控制 |
| A02 | 旧 SDP、替换 DTLS 指纹、错误方向/来源/查看端 | 拒绝会话绑定；不能用媒体握手成功替代设备认证 |
| A03 | view_epoch 撤销后重授，延迟旧帧/旧描述 | 旧画面不进入新 decoder/presenter；输入继续关闭 |
| A04 | 旧窗口句柄/PID 被新应用重用 | 新实例必须重新选源，不接受旧操作 |
| A05 | 旋转/DPI/裁剪/尺寸变化与输入并发 | 旧 geometry 不注入；黑边命中拒绝 |
| A06 | RTP timestamp 回绕、SSRC/track 更换、乱序元数据 | 无歧义关联或拒绝控制，不拿 16-bit frame id 当唯一身份 |
| A07 | 只有 keepalive、重复帧或重绘，来源捕获已失效 | 不更新来源新鲜性；challenge 失败暂停输入 |
| A08 | A 目标持键时切换 B；A 的释放失败/迟到 ACK | B 不接旧键、不获得未确认控制；保留恢复未知 |
| A09 | 本机物理接管、失焦、窗口关闭、锁屏、撤权 | 关门、原账本释放、显示正确状态，无历史输入重放 |
| A10 | 媒体/GUI/codec 进程退出、控制连接断开 | 原 KVM 恢复仍可用；buffer/句柄/租约被回收 |
| A11 | 重复/迟到 handoff 请求与确认 | 幂等且绑定原事务；不提交新事务或报告假成功 |
| A12 | 停放后连接断开、来源屏幕拔出、权限撤回 | 恢复到有效区域或明确 RestoreUnknown，禁止盲目移新窗口 |
| A13 | 伪造帧尺寸、异常 stride、队列满、持续关键帧请求 | 有界资源、受控限速/停止，不绕过身份和尺寸限制 |
| A14 | 文件满速/媒体拥塞与紧急停止并发 | 输入释放、停止优先得到可核验证据；不死锁 |
| A15 | 同 PID 的新窗口/敏感弹窗出现 | 不隐式扩大分享范围；控制暂停并提示 |
| A16 | 新端连接旧端、媒体不支持/codec 不兼容 | 原 KVM 可继续；远程画面明确不可用 |
| A17 | 多 View 共享 Surface 后撤销其中一方 | 无跨许可缓冲复用或越权内容残留 |
| A18 | 无媒体功能启用、重复开关 100 次 | 不遗留采集/codec/worker/监听资源；无固定高频重绘 |

这里列的是测试规格，**没有在本次文档工作中执行这些 runtime 测试**。实施 PR 应将规格落为自动测试、故障注入和各平台原生检查。

## 5. 真机矩阵与性能证据

每份报告记录：完整 commit/包校验值、OS build、CPU/GPU/驱动、输入设备、显示器布局/DPI、网络、codec/硬软编、配置、测试人和日期。双向分别报告，不将一边成功算双向成功。

最少覆盖：

- Windows→macOS、macOS→Windows；普通文字编辑器、浏览器、带菜单/模态对话框的应用。先建立小型明确支持表，再扩大兼容范围。
- Retina 与 Windows 100/150/200%；负坐标、多显示器热插拔、窗口缩放/旋转、遮挡、全屏、最小化。不能采集的状态明确显示，不盲目回退整屏。
- Bluetooth/USB 输入、Ctrl/Alt/Command、左右修饰键、滚轮、拖动及 IME。先支持物理键模式；文本/组合输入若另行实现必须有独立模式和权限，不同时重复提交。
- UAC/锁屏/Secure Input、权限拒绝/撤销、睡眠唤醒、双方进程崩溃、拔网线/Wi-Fi 重连、来源窗口退出。
- 正常 LAN 以及受控 1%/5% 丢包、50 ms RTT、抖动/限带宽；观察降级、重建和故障停止，不把压力条件下的未达帧率伪装为达标。

RW04 起点为 1080p30 SDR/单来源；120 ms P95 input-to-photon 是明确设备/网络下的初始目标，只有 RW05 接入后才能测完整交互。必须同时报告失败率、P50/P95/P99、最长卡顿、实际帧率、文字质量、CPU/GPU、内存/显存和码率。

至少做 8h 会话观察和 100 次启停/故障恢复；正式发布沿用项目既有更严格长期门槛。内存、句柄或缓冲持续增长阻断放行。没有可测数据时写 unavailable，不填 0，不把 API submission/自动呈现回调当物理显示/输入验收。

窗口停放额外要求：保持源端可恢复入口；接收端崩溃、来源 GUI 崩溃、显示器拔出、系统拒绝移动均能给出正确恢复状态。不满足则该平台组合只能提供来源可见的窗口分享，不提供“无缝移走”宣传。

## 6. 发布、回滚与安全准入

每个实施 PR 必须包含：对应 RW/原任务 ID、范围、协议影响、依赖及许可证、精确候选 CI、未测平台、资源结果、真实验收范围和回滚方法。

基于 Rust 变更执行项目已有 fmt、严格 Clippy、locked tests/build 和相关进程/GUI smoke；libwebrtc/平台 bridge 另外执行对应 C++/Swift/SDK 构建与 sanitizers/故障测试。测试不支持的环境如实跳过并保留待验，不删除 gate。

新媒体 feature 默认关闭；不自动监听公网、不部署服务、不安装驱动、不购买证书、不修改用户系统安全。本次文档不授权上述操作。

回滚优先停止新媒体会话、撤销独立许可、恢复属于本会话的来源窗口，再退出/移除 media worker。原身份、v5 KVM、文件内容和既有配置保留。遇到恢复未知不以删除日志/清空配置掩盖。新配置使用独立版本化 namespace；未来版本配置保留而非覆盖。

合并经 CI、架构/安全审查和 Owner 批准；只建小分支/Draft PR，不 force-push，不直接改 main，不自动合并集成分支或 #69。
