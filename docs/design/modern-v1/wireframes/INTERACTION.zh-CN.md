# 现代界面线稿交互说明

设计线稿 · 非运行界面。第二阶段结构稿，待用户定稿后再开发。本批新增SVG及静态PNG预览，不修改运行代码、配置、身份或系统权限。

## 本批入口

- `01-device-hub.svg`：默认设备页，仅本机与一台对端两张卡。
- `02-screen-layout.svg`：独立“屏幕布局”标签，只调整两台主屏的四向关系。
- `03-add-computer.svg`：添加电脑弹层，示例停在“身份尚未准备”的显示短码分支。

三图画布为 1440 × 960，左导航固定 190 px。文字保留为 UTF-8 SVG text，可直接编辑；中性灰色用于层级，蓝色仅标注索引。不存在脚本、外链、远程字体或已绑定的交互。

## 结构与主流程

设备页默认展示两张卡。连接状态与输入状态分别标记；“已连接”只表示通信事实。对端 OS 未知时使用通用电脑图形，不从昵称猜测系统。设备详情从卡片入口按需打开抽屉，关闭后回到原上下文，不保留第三栏。

同一上下文只有一个主操作。设备页示例为“检查本机键鼠权限”；权限就绪后才替换为“开启键鼠协同…”。标签切到布局页后，唯一主操作变为“应用相对方向”；添加弹层内则由当前步骤决定主操作，不叠加多个实心按钮。

“停止协同”和“恢复本机”固定在右上角，切标签或打开添加弹层后仍可见、可达；无会话时停止入口禁用并说明原因。恢复入口不会把恢复请求当作清理成功。恢复未确认时阻止新键鼠会话，并引导先松开两端按键与鼠标按钮。

屏幕布局只呈现本机主屏与对端主屏。示意框不是实际屏幕尺寸；未知数据明确写“尺寸未知”，不填造分辨率。拖动与四向按钮表达相同的上、下、左、右关系。正在协同时锁定拖动、四向按钮与应用操作；停止并收到清理完成事实后才解锁。不扩展到多屏或像素级拼接。

本机鼠标保留“窗口内预览”标识，全局 G1 明确标“开发中”；剪贴板与文件标“开发中，尚未接入”。这些入口不表现为可执行的全局动作或数据共享授权。

## 状态 → 唯一主操作

优先级沿用 `desktop_state::present`：恢复未确认 / 停止清理优先于普通连接和权限状态；Native 已运行时不被普通权限提示覆盖。只读的限制不隐藏停止和恢复入口。

| 状态 | 面向用户的事实 | 唯一主操作 | 边界与补充状态 |
|---|---|---|---|
| 未登记 | 尚未记住另一台电脑 | 添加另一台电脑 | 进入显式身份准备和双边核验；不自动授信 |
| 已登记离线 | 已记住，尚未连接 | 支持 Native 且权限就绪：开启键鼠协同…；权限未就绪：检查本机键鼠权限；Native 不支持：连接电脑 · 仅通信 | 三者按实际条件择一；不从已登记推导可控制 |
| 连接中 | 正在等待两台电脑连接 / 等待对端就绪 | 等待当前操作完成 | 等待对端、Probe、失败清理时不显示再次启动；已有状态代码允许的 Communication 准备入口按实际 Snapshot 呈现，不重复发起连接 |
| 仅通信 | 已连接，键鼠尚未开启 | 权限就绪：开启键鼠协同…；未查或不可用：检查本机键鼠权限 | 不支持 Native 或只读时不提供输入启动；连接不等于允许接收 |
| 权限未查 / 过期 | 开始前先检查本机键鼠权限 | 检查本机键鼠权限 | 检查中替换为等待；失败、拒绝、未知、Unsupported 分别显示原有说明，不能归为就绪 |
| 权限就绪 | 本机权限已就绪 | 开启键鼠协同… | 仍需独立 Native 确认；接收由另一台单独允许，不因按钮变色取得权限 |
| Native 运行 | 当前在本机 / 正在控制对端 / 正在被对端控制 | 无新增启动操作 | 固定停止 / 恢复可用；切换待确认、拒绝、超时按现有事实显示；布局锁定 |
| 停止中 | 正在等待输入清理和连接结束 | 查看恢复指引 | 不重启、不将终止回执前的状态当作空闲；固定安全入口保留 |
| 恢复未确认 | 输入恢复需要确认 | 查看恢复指引 | 松开两端按键与鼠标按钮；确认前不开始新会话 |
| 只读 | 这个窗口只读，资料已保留 | 无状态写入主操作；到设置查看原因 | 不提供添加、布局写入或新启动；已有停止与恢复仍可使用 |

“开启键鼠协同…”表示进入既有确认流程，不表示直接执行 Native。连接失败、首次等待超时、配对进行中与登记待回执继续使用现有提示，不用“就绪”覆盖。

## 添加电脑

1. “显示配对码”和“输入配对码”二选一。切换后替换内容区，不同时摆放两套表单。
2. 本机身份未准备时，先说明首次需要创建本机配对身份，再由用户明确点击“准备并生成配对码”；图中短码区仅为“配对码将在此显示”占位，复制不可用。身份已准备时不重复生成或覆盖既有身份。
3. 显示分支准备身份后生成本次短码，再等待另一台输入；输入分支准备身份后显示空输入框，由用户填写另一台提供的短码。不得写死示例码或把占位内容用于运行时认证。
4. 双方进入核验步骤，显示实际设备身份和可核对信息，分别确认后才记住设备。登记待对端回执时显示等待，不宣称登记完成或可控制。
5. 附近发现默认关闭，仅在明确开启后用于本次配对；不得把发现当作信任或自动登记。取消结束当前流程，不增加可信设备。
6. 完成页只确认设备登记结果；不会自动开启键鼠或内容共享。键鼠回到设备页，经过独立 Native 确认及对端单独允许接收。

## 开发注解：沿用事实，待开发时保持

- 校对基准：分支 `modern-ui-concepts`，读取时提交 `de431b7119516097cc3cd41ee014277e0dee0722`。事实来源为 `apps/peerglide-gui/src/desktop_state.rs` 与 `apps/peerglide-gui/src/worker_permissions.rs`；本文是现有行为的展示映射，不增加后台能力。
- `worker_permissions` 的观察新鲜度为 30 秒，从工作进程检查完成时的 `Observation.finished` 起算；不是从 GUI 读取结果或打开页面时重新起算。到期回到 `Unchecked`。检查仅为只读观察，不是输入授权，也不证明实际注入成功。
- 权限报告来自实际同包 worker 的既有只读检查路径。`Ready` 仅指观察到的本机权限条件；Native 开启仍须独立确认，另一台必须单独允许接收。信任不包含输入、剪贴板、文件或动作授权。
- 取消、超时、陈旧结果或上下文已改变的回执不得增加信任、刷新授权或开启输入。显示等待、失败或重新核验；登记待回执不能包装成完成。此条为既有边界保留要求，未在本批重新审计配对实现。
- 停止 / 恢复以现有 worker 回执和清理结果为事实。Native 运行、本机输入归属及恢复状态优先呈现；不因权限观察过期而伪造已停止或已恢复。
- 细节仅用于开发注解、必要说明或按需详情，不把工作进程、token、超时实现和协议字段塞入产品主流程。
