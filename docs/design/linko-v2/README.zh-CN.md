## 输入与这次要解决的问题

本次核读了用户提供的三设备参考图、`kvm-3c11a88/images` 下 1280 × 800 / 920 × 700 两张真实 CI 界面，以及 `linko-v1/wireframes`。用户参考图的构图、设备材质和信息密度优先于早期平面卡片稿；其中第三台设备、假延迟、传输记录与已开启数据开关不进入新稿。

当前实图已有真实字体、类型分支和清晰安全入口，差距集中在以下位置：

1. 品牌虽靠顶，图标、Linko、下置“屏跃”与首导航之间仍形成高而空的品牌带；导航起点偏低。
2. 页面标题、停止/恢复、连接详情被分成不同层级；顶部文案与右侧“已连接”卡重复，主操作的优先级反而不清楚。
3. 右侧单独的连接卡再次放停止按钮，占用整行，却没有清楚并列“通信已连接”和“键鼠未开启”。
4. 左侧详情每张卡重复会话输入状态，右侧又有“所选设备”和输入状态；元数据与选择信息密度失衡。
5. 参考图的硬件有共同基线和轻选择态；未知类型不应以大白矩形冒充某种机型，也不应靠虚构系统信息补齐卡片。

V2 采用同一套 32px 标题栏示意、176px 侧栏、64px 统一工具栏和 20px 内容边距。标题、页面目的、唯一主操作、停止、紧急恢复在同一工具栏；真实通信/键鼠状态只集中到右侧“当前会话”，本机许可单独呈现。

## 线稿状态与数据口径

两张工作区图表示**同一设计状态**：一台已登记对端、通信已连接、键鼠未开启、检查尚未进行、本机接收默认关闭。它不是首次启动自动连接，也不是当前 Mac 或真实双机的状态证明。

为说明硬件分支，图内本机采用“系统报告为 macOS、类型已知为笔记本”的设计条件，显示“这台 Mac / macOS / 笔记本电脑”；这不是对用户当前 Mac 机型的判断。实际实现必须读取现有类型检测：台式机换台式素材，笔记本换笔记本素材，未知换中性双屏符号；不能固定本机等于笔记本或对端等于台式。

对端只假定已有有效登记，名称“已登记电脑”为线稿占位，不新增任何真实登记。对端系统不显示，设备类型明确“类型未识别”，用无支架、无笔记本底座的通用双屏符号。图内所有硬件画面为原创灰阶示意，不读取或展示屏幕内容，不代表分辨率、系统壁纸或远程视频。

蓝色只用于主操作、本机选择和必要焦点；不代表权限就绪。连接状态使用文字，不用绿色数字或开关暗示 Native 已运行。无延迟、在线数量、传输历史、进度或示例第三台电脑。

## 区域尺寸与首屏边界

坐标均从 SVG 左上角起算；窗口尺寸包含 32px 原生标题栏示意。`x / y / w / h` 单位为逻辑像素。

32px 仅用于本稿解释窗口边界，不是系统标题栏高度契约。Windows 使用原生窗口 chrome，macOS 也沿用原生窗口装饰。实际布局应按 client viewport 的可用尺寸计算，不硬编码系统标题栏高度；不能因为本线稿而静默改动当前应用的 `min_inner_size`。

原始 CI 图没有本稿所画的32px原生标题栏，画布上边界约 y=112，不能直接把新 y=116 宣称为“提前了若干像素”。本批可量化的是新区域预算与边界；相对当前用户宿主窗口的真实节省量，需拿同口径原生窗口再测。这里不声称已经减少了某个宿主实测高度。

首屏几何证据：紧凑稿顶部主操作范围 x=486–650、停止 x=658–750、紧急恢复 x=758–900，三者均 y=46–82；详情卡底部 y=612，布局说明与右列能力入口的文字底部不超过 y=640，距 y=672 底栏至少32px。标准稿对应的三个安全/主操作按钮同为 y=46–82，最右到 x=1260，留20px边距。未靠增加920窗口高度或隐藏安全入口容纳内容。

字号层级：页面标题26、品牌24、弹窗标题/小节16、正文14、辅助12–13；设备名14/600。SVG 字体栈使用本机中文字体，实际字宽仍需 PNG 全尺寸审版。所有按钮高36；图内方向和缩放控件28，未来实现应保留至少现有键盘焦点与可访问性，不以本线稿静态装饰替代真实控件。

## 工作区的交互提案

### 标题、主操作和安全入口

- 顶部副摘要是页面目的“拖动电脑，安排主屏的相对位置。”，不再重复通信与键鼠状态。已登记且允许进入准备流程的正常状态中，蓝色主操作统一为“开启键鼠协同…”，点击**只打开独立准备弹窗**，不是立即启动 Native 或自动授权。系统权限是开启过程，不长期占据最大的任务按钮。
- 这是一项交互提案：后续实现需要允许在权限未查/过期时打开准备界面，不能把 Readiness 未查解释成 Native 已可用；平台支持、有效登记、配置可写、无配对/回执阻塞、无停止/恢复阻塞等既有入场条件继续成立。最终确认仍严格要求新鲜 Ready、本次独立明确同意、上下文有效及实际输入程序再次检查。
- 右侧“本机控制”只显示“系统权限 / 真实检查状态 / 权限详情”与“开启时会检查并确认控制范围。”，不再重复教学检查步骤。已授予、拒权、未知与过期均据实在主面板可见；恢复异常优先显示，不能藏进悬停文案。
- 检查不联网、不捕获输入、不申请系统权限，也不等于实际输入可用或对端许可。
- 停止与紧急恢复常驻所有页面。没有运行会话时，停止原位禁用；紧急恢复仍可请求停止/查看恢复。不得因为“键鼠未开启”而禁用正在运行的通信会话停止。
- “连接与身份详情”移到右侧当前会话卡。打开后按需查看连接资料、证书、地址与原始诊断；主画布不显示工程日志。
- 通信会话切换 Native 仍先停止并确认清理，随后才重新连接；失败不自动继续，不新增并行捕获。

### 画布与设备详情

- 一张浅渐变薄边画布。缩放/适配留在画布上沿；硬件、设备名、状态分别共用底线，选中只轻围设备主体，不再套一层大蓝卡。
- 选择节点或详情卡只改变选择，不写身份、权限或连接；所选卡边框与画布选择一致。不新增假的定位或断开动作。
- 四向是本机与一台对端主屏的相对方向。不是自由坐标多屏、自动排列、远程画面或分辨率拼接。缩放只调整示意观看比例。
- 活动会话图中四向按钮禁用且说明“会话中已锁定”。配对、待双端回执、恢复未确认、配置只读等继续阻止布局写入；失焦、切页、Esc、上下文变更取消未提交拖动，冲突拒写需回滚。
- 详情卡只保留名称、实际连接/登记、系统（已知时）及真实类型。输入归属集中到“当前会话”，避免把会话状态误标成设备固有属性。

### 本机许可与尚未实现能力

- 本机权限与本机接收控制是两件事。“默认关闭 / 设置”仅控制本机是否接收已登记对端；对端许可由对方独立设置。
- 文件与系统剪贴板明确“尚未接通”，全局手势明确“开发中”；不用已开启开关、不展示假记录。快捷键页保留现有本机鼠标、窗口内预览、手势实验与规则入口，不由重排导航删除功能。
- 音频、多屏、窗口桥、远程空间不进入本轮图或新增入口。

### 异常与默认状态，不用本稿正常态覆盖

| 实际状态 | 主操作 / 信息优先级 |
|---|---|
| 首次使用、未登记 | 添加另一台电脑；画布只有本机与明确添加空位，不出现假对端 |
| 已登记、停止状态 | 键鼠仍未开启；支持的平台显示“开启键鼠协同…”进入准备，未支持时保留仅通信入口 |
| 配对中 / 双端回执待确认 | 当前配对步骤 / 等待；不能被正常启动按钮替代 |
| 权限 Checking / 未知 / 过期 | 主面板与准备弹窗据实显示；仅在弹窗内检查，不显示就绪，不自动保留旧同意 |
| Native 当前在本机 / 控制对端 / 接收对端 | 分别显示实际输入归属，不增加启动动作；保留停止与恢复 |
| 停止中 / 恢复未知 / 清理失败 | 顶部唯一主操作替换为恢复指引；右列优先显示完整恢复状态与动作，不仅放进 hover |
| 只读 / 未来配置 / 登记冲突 | 明确就地提示及保留数据；停止/恢复继续可达，禁止新写入 |
| 等待超时 / 最近失败 | 明确失败与下一步，不把提示藏在不存在的主按钮 hover |

异常信息较长时，右列先呈现当前阻塞与恢复动作，收起低优先级能力说明而非删除安全字段；说明内容可独立滚动，停止/恢复不进入滚动区。恢复、只读和配对异常分支尚未逐个画成 SVG，实现前必须沿已有状态映射验证，不能拿正常态几何当作所有状态都已验收。

## 开启键鼠弹窗：位置固定，过期不重排

03 图是权限检查已过期分支。弹窗外框 580 × 540，位于920窗口 x=170 / y=96，底部 y=636，距离 y=672 底栏36px。1280标准窗口使用同尺寸居中，不拉高整个窗口。

| 固定区 | 坐标与高度 | 内容 |
|---|---|---|
| 标题区 | y=96–148，52px | 开启键鼠协同、关闭 |
| 检查区 | y=148–272，124px | 重新检查、状态摘要、不会联网/捕获的说明 |
| 中间滚动容器 | y=272–512，240px；内视口194 / 284 / 532 / 212 | 检查详情、双方许可、通信先停止、物理接管、快捷键与兼容性说明 |
| 固定确认区 | y=512–636，124px | 独立同意、立即停止恢复、取消、确认开启、恢复语义说明 |

- 顶部重新检查位于 x=594–726 / y=158–194。同意位于 x=194–211 / y=526–543；三操作按钮 y=558–594。过期提示增减或滚动说明均不能移动这些坐标。
- Ready 必须来自实际同包 worker 的权限观察，从 `Observation.finished` 起严格30秒；读界面或重开弹窗不刷新时间，不引入自动续期或倒计时假数据。
- 过期立即清除本次同意，复选框与确认禁用；重新检查通过后仍需用户重新勾选。不能保留旧勾选自动启动。
- 独立勾选不改变对端许可。确认前再次校验新鲜度与现有状态，实际输入程序仍需重新检查；信任或通信连接不能替代授权。
- “取消”对应关闭现有确认流程，关闭/切页清除未确认同意，不写入输入授权。点击背景不能穿透到下层主操作；Esc沿已有取消/拖动规则，不隐式确认。
- 弹窗里保留“立即停止并恢复本机”，不靠点击穿透后面的安全工具栏；确认禁用时该停止入口仍可用。停止请求不等于恢复成功，失败与未知仍保留提示。
- 当前实现已有固定检查/滚动/确认结构；本稿的124px确认区、显式取消按钮和统一工具栏属于下一步排版提案，不宣称已落到Rust。

## 离屏审版结果

三张最终PNG已经逐张查看：标准与紧凑稿的品牌、标题、主操作和安全入口在同一顶部带；中文没有相互覆盖，紧凑卡片及底部说明完整可见；弹窗白底、固定检查/同意区与禁用状态清楚。主操作是“开启键鼠协同…”，权限检查留在准备流程中。文件和剪贴板导航也就地标注“未接通”。

首轮AppKit导出曾忽略样式表和滤镜，使字号/按钮字色错误、画布和弹窗底板缺失。已将所有文字改为显式SVG属性、删除滤镜并重新导出核读；首轮失败图保留在本地验证目录，不作为最终稿。未知设备符号的贯穿斜线也已改为外侧短连接段。源SVG及PNG尺寸、SHA-256和检查边界见[assets.json](assets.json)。

本轮只交付线稿，实际GUI布局等待审稿后实施。Mac应用版本/图标更新属于独立操作，记录在项目VALIDATION，不由这些设计图证明。浏览器未验证。

## 资源、检查与未覆盖项

品牌原样沿用 `../linko-v1/brand/app-icon.svg` 的原创路径与渐变，内联在 SVG 符号中以便离屏渲染；不重新设计系统图标、不修改生产图标资源。灰阶设备插画、导航线条只是本目录线稿表达，不是新的生产图标包。未知设备的两屏通过外侧短直角连接段相连，不再用贯穿屏幕的斜杠，以免与“已连接”状态矛盾。

SVG 使用可移植的元素 presentation 属性：每个文字元素显式声明字体族、字号、字重与颜色，蓝色按钮的白字直接声明 `fill="#FFFFFF"`。不依赖 `<style>` 类或 SVG 滤镜；全部滤镜及引用已移除，画布、设备卡和弹窗由普通矩形背板绘制。本稿不画阴影，渐变与内置 symbol 保留。标题两行基线 y=61 / 83，字号26 / 12，均位于 y=32–96 工具栏内；紧凑主按钮164px宽、14px白字，最终字宽与可读性仍由重新渲染的PNG确认。

本批静态检查范围：SVG XML 可解析、三份根画布尺寸正确、按钮标记几何不越界、紧凑关键内容与底栏保留间距、无脚本/远端图片/外链字体、无本地路径或用户数据。`git diff --check` 另行记录于交付消息。

尚未覆盖：完整设备管理/配对各步骤、所有异常状态独立线稿、深色主题逐页稿、其它尺寸和实际屏幕阅读器行为。SVG 不等于像素级视觉验收；线稿检查未运行 Rust 或浏览器，也未修改 TCC。现用 App 的 GUI 启动、Finder 图标及 Dock 入口验证单独记录在项目 VALIDATION，不能由本目录线稿证明。
