### 1.6 可以借鉴的模式（我的归纳）

1. 动效都是一次性的，由状态变化触发；唯一的持续动画是加载转圈（P6），而且只在异步任务进行中出现。
2. 空闲时不跑任何动画：弹簧（A1、A2）静止后就停止请求帧。这一点与 Linko 的空闲重绘要求一致。
3. 状态用“系统图标加角标”表达（D3–D5），颜色总是配合专属形状，不只靠颜色区分。
4. 危险和告警仍然用句子（B4、B3 的跳过确认），不用图标替代。

## 3. egui 0.37 可实现性、重绘与内存

### 3.1 现状约束（读到的事实）

- `main.rs:1350-1369` `request_activity_tick`：只有 Native 会话、EOF 回收、停止中、待启动、布局请求、发现、权限诊断、手势画布、布局报告、配对轮询这些情况下，才每 100ms 安排一次重绘。稳定的仅通信会话靠 stdout 读线程唤醒，**不再周期重绘**（VALIDATION 第 1820–1830 行：修复后 GUI 平均单核 CPU 从 39.66% 降到 0.76%，峰值 RSS 约 119MiB）。
- 内存 CI（`gui-memory.yml`）：Linux 和 macOS 空闲 180 秒，RSS 上限 512MiB，增长上限 64MiB；另有 30 秒的自有进程资源与 CPU 分账。修改 `apps/peerglide-gui/**` 会自动触发。
- `desktop_style.rs:2` 的模块注释写明：这个文件里不放运行时状态、原生查询、外部资源或重绘计时器。
- 已有的“只重绘一次”先例：权限观察 30 秒到期时 `request_repaint_after(remaining)`（`main.rs:1491-1493`）；手势绘制中 `request_repaint()`（`gesture_lab.rs:254-255`）。测试里已有用 `set_request_repaint_callback` 观察重绘请求的写法（`gesture_lab.rs:387`、`main.rs:2676`）。

### 3.2 可用手段（通用 egui 知识，0.37 未核实）

| 手段 | 用途 | 重绘特性（需在 S0 核实） |
|---|---|---|
| `Context::animate_bool_with_time(id, on, secs)` / `animate_bool_with_easing` | 悬停、选中、展开、显隐的 0 到 1 插值 | 插值没到终点时，egui 会自动请求下一帧；到达后不再请求。 |

### 3.3 动效预算

规则：
1. **空闲时零持续重绘。** 所有动效都必须由一次输入事件或一次状态变化触发，播放时长有上限，结束后不再请求重绘。
2. 不新增任何周期节拍。已有 100ms 节拍时（Native、配对轮询、权限检查中、发现中），等待指示器可以在这些节拍上一步一步地走，但不能自己 `request_repaint()`。在稳定仅通信、已登记离线、空闲这些状态下，一律用静态图形。
3. 预算按**时间**定，帧数按 60Hz 估算；高刷屏（如 120Hz）帧数会翻倍，但时长不变。
4. 动画状态只用固定的 `Id`（按控件或按区域），不在 `Id` 里拼入通知文本或设备名之类会不断变化的内容，所以 egui 内存里的动画表大小是常数级。
5. 不新增纹理：图标用 painter 自绘；现有设备 PNG 的纹理已有复用测试（`visual_assets.rs:129`）。
6. 交互不能依赖动画：动画进行中点击立即生效；把时长设为 0 后功能必须完全一样。

| 动效 | 参考 | 时长 | 约帧数@60Hz | 触发 | 重绘条件 |
|---|---|---|---|---|---|
| M1 悬停底色和描边淡入 | D1、D7 | 80ms | 5 | 指针进入或离开 | `animate_bool`，结束即停 |
| M2 选中底色、选择环淡入 | D2、A5 | 120ms | 7 | 点击设备或屏幕、键盘焦点 | 同上 |
| M3 侧栏折叠和展开 | O1 | 200ms，`cubic_out` | 12 | 点击开关、窗口变窄 | `animate_value`；文字在宽度过半后才显示，避免挤压 |
| M4 页面和视图切换（滑入 12px 加淡入） | O5 | 160ms | 10 | 导航 | 一次性 |
| M5 标题栏状态胶囊变化（缩放 0.92 到 1 加淡入） | O4 | 180ms | 11 | `View` 的标题或色调变化 | 一次性；内容不变时不重播 |
| M6 状态角标弹出（缩放 0.3 到 1） | D3、D4 | 200ms，轻微回弹 | 12 | 状态从无到有 | 一次性 |
| M7 拖动松手后显示器回弹到合法位置 | A1 | 220ms，`cubic_out` | 13 | 松手、撤销拖动 | `animate_value`，用现有 `try_set_edge` 的结果作为目标 |
| M8 输错时抖动 | P1 | 360ms，五个点衰减 | 22 | 配对码错、地址格式错 | 一次性 |
| M9 成功对勾或失败叉号描线 | P5、B2 | 240ms | 15 | 配对成功或失败、权限检查完成 | 一次性 |
| M10 对话框高度变化 | P3 | 200ms | 12 | 配对阶段切换 | `animate_value`；固定尺寸的 W3 不用 |
| M11 等待指示器（8 格离散转圈） | P6 | 不定 | 不额外增加 | 只在已有 100ms 节拍期间 | 每个已有节拍走一格；节拍停止就静止 |
| M12 列表项进出 | D10 | 180ms | 11 | 发现结果增减 | 一次性 |

一次交互最多同时播放 3 个动效，总时长不超过 360ms，之后回到零重绘。

### 3.4 新增回归测试（建议，S0 写入）

1. `animations_settle_to_zero_repaint`：用无头 `Context` 跑完 M1–M10 的触发路径，然后再推进超过 0.5 秒，用 `set_request_repaint_callback` 断言之后再也没有新的重绘请求。
2. `idle_workspace_has_no_periodic_repaint`：空闲、已登记离线、稳定仅通信三种状态各跑 100 帧（不注入任何输入），断言没有请求时延小于 1 秒的重绘。可以复用 `main.rs:3175,3214` 两个测试的思路。
3. `animation_time_zero_is_functionally_identical`：`animation_time = 0` 时，主路径（添加、开启确认、停止、拖动保存）的结果不变。
4. 资源对照：在 gui-memory 的两个作业里，与 `130cd8e` 的 0.76% CPU 和约 119MiB 对比，新增偏差写进 VALIDATION。不改 512MiB 和 64MiB 这两个阈值。

### 4.1 信息架构（页面树）

参照 Oink 的单窗口结构：可折叠的设备侧栏、画布首页、底部图标操作、标题栏状态胶囊。

```
主窗口
├─ 标题栏：侧栏开关 | 状态胶囊（居中） | 停止 · 紧急恢复（右侧固定）
├─ 侧栏（展开约 240px，折叠 64px）
│   ├─ 设备列表：本机、对端（角标表达状态），点击即选中（只改查看对象）
│   ├─ ＋ 添加电脑（未登记时）/ 重新核验（已登记时，放进设备菜单）
│   └─ 底部图标：快捷键与手势 · 设置 ·（版本号小字）
├─ 首页（默认）：画布（两台主屏）+ 右侧上下文栏（所选设备）
│   ├─ 上下文栏：连接行 / 键鼠行 / 接收控制行 / 本机权限行 / 唯一主按钮 / 协作能力（未接通）
│   └─ 设备详情抽屉（ⓘ）：地址、指纹、仅通信、连通检查、手动核验、发现、移除信任
├─ 接收控制（从接收控制行进入，返回箭头）
├─ 快捷键与手势（返回箭头）
│   ├─ 组合键（键帽图形）
│   └─ 本机鼠标：规则 | 录制测试（G1 禁用横幅保留）
├─ 设置（返回箭头）：常规 | 权限 | 诊断
│   └─ 只读、退出入口未就绪这类警告卡置顶
└─ 对话框：添加电脑（W1）、高级核验（W2）、开启键鼠（W3）、撤销、重置、强停、恢复（W4）、操作详情（W5）
```

变化：
- 原来的“设备”和“屏幕布局”合并为首页：侧栏放设备名单，画布负责布局。
- “总览”的内容并入标题栏胶囊和上下文栏。
- “文件传输”和“剪贴板”不再占导航（见决策 2）。
- 布局子页 L9 与首页重复，删除，功能由首页承担。
- 所有入口仍然可达，任何功能都没有删除。

### 4.3 状态到视觉的映射

两个位置共用同一套映射：标题栏胶囊（全局）和设备角标（每台设备）。数据来自 `desktop_state::present` 和 `input_label`，**只做展示，不改优先级**。

| 状态（来源） | 颜色（Tone） | 形状 | 动效 | 胶囊文字（≤6 字） | 必须伴随的句子 |
|---|---|---|---|---|---|
| 未登记 | Accent | 虚线空位加号 | 无 | 未添加 | 无 |
| 已登记离线 | Neutral | 空心圆 | 无 | 未连接 | 无 |
| 连接中、等待对端（`waiting_for_peer`） | Accent | 圆弧（8 格） | M11，只随已有节拍 | 等待另一台 | “约一分钟，可随时停止”（K） |
| 等待超时 | Warning | 空心圆加时钟 | M6 | 等待超时 | detail（K） |
| 仅通信已连接 | Good | 实心圆 | M6（只在刚连上时） | 已连接 | 无（主按钮说明下一步） |
| 权限未查或过期 | Accent | 盾牌轮廓 | 无 | 需检查 | 无 |
| 权限检查中 | Accent | 盾牌加圆弧 | M11 | 检查中 | 无 |
| 权限拒绝、未知、Secure Input、失败 | Warning | 盾牌加感叹号 | M6 | 需处理 | 原因句（K，见 `worker_permissions.rs:37-54`） |
| 权限就绪 | Good | 盾牌加对勾 | M9 | 权限就绪 | “30 秒内有效”（悬停提示） |
| 键鼠开启，当前在本机 | Good | 本机设备上一个光标角标 | M6 | 本机控制 | 无 |
| 正在请求切换（Pending） | Accent | 光标加向外箭头 | M11 | 切换中 | 无 |
| 控制另一台（ControllingRemote） | Accent | 对端设备上的光标角标，连线带方向箭头（静态） | M6 | 控制另一台 | Ctrl+Alt+Esc（悬停提示加快捷键页） |
| 另一台正在控制本机（ReceivingRemote） | Accent | 本机设备上的反向箭头角标 | M6 | 被控制中 | “第一下操作只用于收回控制”（K，在上下文栏） |
| 切换被拒绝（Denied） | Warning | 箭头加斜杠 | M6 | 切换被拒 | detail（K） |
| 切换超时（TimedOut） | Warning | 箭头加时钟 | M6 | 切换超时 | detail（K） |
| 对端无鼠标能力（PeerUnavailable） | Warning | 箭头加问号 | M6 | 对端不可用 | detail（K） |
| 正在恢复（Recovering） | Warning | 双向弯箭头 | M11 | 正在恢复 | “先松开按键和鼠标按钮”（K） |
| 停止中 | Warning | 方块加圆弧 | M11 | 正在停止 | detail（K） |
| 恢复未确认 | Danger | 八边形加感叹号，实心红底 | 只有 M6，**不闪烁** | 恢复未确认 | 横幅（K），锁定布局 |
| 待回执 | Warning | 半填充的链环 | 无 | 待回执 | “暂不能连接；可重新核验或撤销”（K） |
| 连接失败 | Warning | 断开的链环 | M6 | 未完成 | detail（K） |
| 只读 | Warning | 锁加文档 | 无 | 只读 | “资料已保留；停止和恢复仍可用”（K） |
| 配对中 | Accent | 链环加圆弧 | M11（只随配对轮询） | 正在添加 | 无 |
| 拒绝（配对码错） | Danger | 叉号 | M8 加 M9 | 码不正确 | 错误句（K） |

规则：
- 每种状态的形状都不同，颜色只是辅助；Warning 和 Danger 必须同时显示胶囊文字。
- 绿色只表示“连接或检查的事实”，从不表示授权。“接收控制”一栏永远显示开或关的文字加锁形图标。
- 恢复相关的状态不做闪烁、呼吸这类持续动画，避免变成持续重绘，也避免被误解为“正在自动处理”。

### 4.4 图标策略

- **来源**：在 `desktop_style.rs` 旁边新增 `icons.rs`（只放纯绘制函数，没有状态），用 `Painter` 的线段、圆弧、多边形自绘，统一 1.4px 线宽，16px 和 20px 两档网格。现有自绘图标（`desktop_style.rs:372-459` 的导航图标、`brand_mark`、`detail_icon`、`monitor`）迁移进去复用。
- **不引入**图标字体或 SVG 渲染依赖（Phosphor、Material Symbols、`egui_extras` 的 svg 等）。原因：这些都要登记第三方许可（`tools/third_party.py` 在 CI 里执行），还要过依赖审计；自绘方案零依赖、零新纹理、零许可负担。
- 不使用 egui 默认字体里的 emoji 或符号字形作为界面图标：它们在各平台显示不一致，许可登记情况本次没有核实。
- 字体继续只用捆绑的 `NotoSansSC.ttf`（OFL，`assets/fonts/OFL.txt`）及其三档字重（`main.rs:76-88`），不新增字体。
- 不复用 Oink 的任何图标路径或品牌图形，只借鉴“系统图标加角标、挖空描边”这类结构概念，路径全部重画。
- 每个图标按钮都必须有无障碍名称（用 `Response::widget_info` 或带文字的 `on_hover_text`），名称就是原来的中文标签。

### 4.6 可访问性底线

1. 对比度：正文和小字对背景 ≥4.5:1，图标和焦点环对相邻颜色 ≥3:1。沿用 `linko-v1` 已核算的色值（辅助文字 `#5F6F85`），新增的角标颜色在 S0 用脚本核算并写进文档。
2. 键盘可达：侧栏开关、设备行、画布中的每台显示器、四个方向箭头、缩放按钮、上下文栏所有按钮都能用 Tab 到达，焦点环清晰可见（2px 强调色，参照 D2）。拖动必须有方向按钮作为等价入口（现状已有，保留）。Ctrl+Alt+Esc 的全局处理保留（`desktop_ui.rs:1289-1294`）。
3. 悬停提示只做补充：任何 K 类信息都不能只放在悬停提示里。图标按钮的悬停提示等于它的无障碍名称。
4. 颜色不是唯一编码：见 4.3 的“形状”列。
5. 动效不是唯一反馈：M8 抖动的同时一定有错误文字，M9 对勾的同时一定有状态文字。
6. 窗口最小 920×700 时，主按钮、停止和紧急恢复必须完整可见（现有测试 `essential_context_and_connection_details_fit_the_supported_first_viewport` 的要求保留）。

## 6. 需要用户拍板的决策

1. **导航结构**：推荐采用 Oink 式单窗口（可折叠设备侧栏、画布首页、标题栏状态胶囊、设置和快捷键改为返回式子页），替代现在的 6 项文字导航。理由：最大限度减少文字和跳转，所有功能仍然可达。代价是 gui_smoke 和导航测试需要相应调整。
2. **文件传输和剪贴板**：推荐从导航中移除，改为上下文栏里一行灰色“文件·剪贴板 未接通”（点击后看完整说明）。理由：PRODUCT.md 允许“明确标注或隐藏”；这两页现在没有任何功能，保留一行标注就满足诚实要求。另一个选项是保留现有两页。
3. **安全对话框的文字处理**：推荐只重新排版（图标加要点、每条 ≤30 字），并用逐条语义对照表验收，不删减任何语义。理由：AGENTS.md 要求授权和恢复提示保持明确。另一个选项是进一步压缩，但需要每一句都由你逐条确认。
4. **图标来源**：推荐用 egui Painter 自绘，不引入图标字体或 SVG 依赖。理由：零新依赖、零许可登记、零新纹理。代价是图标数量多（约 30 个），绘制工作量较大。
5. **减少动效**：推荐第一期不加开关，所有动效都 ≤360ms、一次性、无持续动画；如果之后要加“减少动效”开关，单独开一个 PR 扩展桌面偏好存储（版本化）。理由：避免在 UI 重做里顺带改存储 schema。egui 读不到系统的“减少动态效果”设置（猜测，未核实）。
6. **等待类状态的指示**：推荐只在已有 100ms 节拍期间（Native、配对、权限检查、发现）显示离散转圈；稳定仅通信、离线、空闲状态一律静态。理由：保持 VALIDATION 中 0.76% CPU 的空闲收敛成果。代价是等待动画在 10Hz 下观感偏“一格一格”。

其他需要知会的决定（我按推荐处理，除非你另有意见）：
- 术语统一为“另一台”，界面不再出现“对端”。
- 标题栏状态胶囊在 Warning 和 Danger 状态下必须带 ≤6 字的文字。
- 托盘状态角标不做（会与故障流冲突）。
